# Contributing to pytestpp

Thanks for your interest! This project is MIT-licensed and open source.

## Development setup

```bash
python -m venv .venv && . .venv/bin/activate
pip install -e ".[dev]"        # once a `dev` extra is defined
pip install -e .               # minimal: the package + its runtime deps
pytest                         # run the test suite
```

## Package conventions

- **Source layout** — code lives in `src/pytestpp/`.
- **Versioning** — semantic versioning via `setuptools-scm`; versions are
  derived from git tags (`v1.2.3`), not edited by hand. Do **not** bump a
  `version` field in `pyproject.toml`; tag the repo instead.
- **`_version.py`** is generated by `setuptools-scm` at build/install time and
  is not committed by hand.

## Making a change

1. Branch off `main` (`git switch -c fix/...`).
2. Add the change and a test; update `docs/usage.md` if CLI behavior changed.
3. Run the suite: `pytest`.
4. Add a `CHANGELOG.md` entry under `[Unreleased]`.
5. Open a pull request.

## Releasing a new version

1. Update `CHANGELOG.md` (move `[Unreleased]` to the new `[MAJOR.MINOR.PATCH]`).
2. Tag: `git tag v1.2.3 && git push --tags`.
3. CI (or your runner) builds with `setuptools-scm` and uploads to PyPI.

## Guidelines

- Keep behavior predictable: the smart layer must always fall back to a plain,
  full `pytest` run rather than erroring or silently skipping tests.
- Cover CLI flags and the smart-default fallback matrix with tests.
- Preserve the exit-code contract: the command returns the underlying pytest's
  exit code.
- Follow [PEP 8](https://peps.python.org/pep-0008/) and keep functions small.
